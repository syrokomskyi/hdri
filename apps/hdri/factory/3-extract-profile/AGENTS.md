## Profile closure (RFC-0104)

### Frozen internal stage graph

The profile extraction pipeline follows a frozen internal stage graph:

```
homepage-capture → link-discovery → detected-page-capture → signal-extraction → profile-closure
```

Each stage has a distinct `stageId` in the execution journal. The `stageId` union type in `WorkKey` (`packages/factory-core/src/lib/quarter-contracts.ts`) includes `"homepage-capture"` and `"detected-page-capture"`.

### Context-keyed extraction

All `ext_*` tables use a composite primary key: `(asset_id, page_observation_id, effective_url, content_sha256, extractor_ver, policy_hash)`. This ensures identical HTML observed at two origins retains separate owners. The `content_sha256`-only primary key is retired.

### Result set hash verification

Profile closure requires all four child seals (homepage-capture, link-discovery, detected-page-capture, signal-extraction). The expected and observed result set hashes must match. A missing evidence entry causes a hash mismatch and blocks closure.

### Detected-page ownership

Detected-page ownership uses the explicit context key (`asset_id`, `page_observation_id`) from `ext_*` rows — not `LIMIT 1` content-hash guessing. The `FetchDetectedPagesGogol` reads `asset_id` and `page_observation_id` directly from ext_* rows and uses them for precise `site_pages` lookup.

### Pagination

The extraction runner processes at most 256 pending metadata rows per batch (`PAGINATION_LIMIT = 256`). Keyset pagination with immediate per-result checkpointing replaces full-table result accumulation.

### Provenance fields

`upsertPageObservation` accepts optional `urlFinal`, `deviceId`, `sourceToken`, and `measuredAt` parameters. `CrawlGogol` and `FetchDetectedPagesGogol` pass these from the brief.

### Coverage diagnostic

Run `pnpm --filter @syrokomskyi/site-profile profile:coverage -- --capsule <path> [--json]` for a read-only diagnostic report of extraction coverage per `ext_*` table.
