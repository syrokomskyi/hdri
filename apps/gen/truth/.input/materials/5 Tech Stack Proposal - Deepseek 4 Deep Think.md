# Представим, что мы хотим создать такую систему - платформу разработки видео произведений. Поработаем сейчас над тем, на каком стеке это лучше реализовать. Интересует технологический стек.

---

Спроектировать стек для системы такого масштаба — значит заложить фундамент, который позволит ей расти от минутных объясняющих роликов до полнометражных фильмов, как того требует архитектура. Основываясь на анализе, вот предлагаемый технологический стек, разбитый по функциональным слоям.

### 🎯 Ключевой принцип выбора стека

Главный вывод из анализа — **система не должна переписываться при масштабировании**. Поэтому стек строится вокруг **гибкого, расширяемого ядра**, где добавление новых возможностей происходит через регистрацию в реестрах, а не через изменение кода【15†L1-L3】. Это достигается за счет строгого разделения на **Story Graph** (семантика и логика повествования) и **Production Graph IR** (инструкции для рендеринга).

### 🧠 1. Ядро и Оркестрация (Backend & AI)

Это мозг системы, управляющий агентами и бизнес-логикой.

*   **Язык**: **Python 3.11+** — бесспорный лидер для AI/ML задач, с богатой экосистемой для работы с LLM, векторами и графами.
*   **Веб-фреймворк**: **FastAPI** — для создания высокопроизводительных асинхронных API, идеально подходит для общения между агентами и фронтендом. Альтернатива — **Hono** на Node.js.
*   **Оркестрация агентов**:
    *   **LangGraph** или **AutoGen**: для создания графов агентов, управления памятью, состояниями и сложными взаимодействиями.
    *   **Код как оркестратор**: в духе подхода, где LLM (например, Claude Code, Cursor) читает манифесты и вызывает Python-инструменты, а не жесткий рантайм-оркестратор.
*   **Работа с LLM**: **LangChain** или **LlamaIndex** для унифицированного интерфейса к моделям (Gemini, GPT, Claude, локальные Open-Source модели).

### 🗄️ 2. Хранилище данных (Data Layer)

Здесь хранятся два ключевых графа и все метаданные.

*   **Основная БД**: **PostgreSQL 16** — надежное, транзакционное ядро. Критично с расширениями:
    *   **`pgvector`**: для хранения и сравнения эмбеддингов лиц, голосов, сцен. Используется для `IdentityModel` и `continuity-check`.
    *   **`uuid-ossp`**, **`citext`**: для уникальных идентификаторов и регистронезависимых строк.
*   **Графовая БД**: **Neo4j** или **Apache TinkerPop/Gremlin** — для эффективного хранения и обхода **Story Graph** (персонажи, факты, связи, сцены).
*   **Кэш и очереди**: **Redis** — для хранения сессий агентов, блокировок (lease), быстрого кэширования промежуточных результатов рендеринга и организации очередей задач.
*   **Хранилище объектов**: **Amazon S3** / **MinIO** — для хранения исходных медиа (референсы), ассетов, промежуточных (T0, T1) и финальных (T3) видео.

### 🎨 3. Production Graph и Рендеринг (Rendering Engine)

Этот слой отвечает за превращение абстрактных инструкций в пиксели и звук.

*   **Базовый рендерер**: **Headless Chromium** (через **Playwright** или **Puppeteer**) — основа для T0-рендера (раскадровка) и простого 2D-композитинга, как в Editframe.
    *   **`Chrome HeadlessExperimental.beginFrame` API** для покадрового захвата.
*   **Кодирование видео**: **FFmpeg** — для кодирования последовательности кадров в финальный MP4-файл.
*   **3D и продвинутый визуал (T1-T3)**: **Three.js** (в рантайме Node.js) — для генерации превизов (T1) с 3D-сценами, камерами и блокингом персонажей【9†L16】. Для высококачественного финального рендеринга (T3) может потребоваться интеграция с профессиональными движками через API.
*   **Аудиодвижок**: Node.js с **Web Audio API** (или его реализации, например, `node-web-audio-api`) для построения графа шин/сендов и применения loudness-constraints【7†L25-L26】.

### 💻 4. Пользовательский интерфейс (Frontend)

Интерфейс для оператора, где он видит превью, оставляет фидбек и управляет проектом.

*   **Фреймворк**: **Next.js 15** (App Router) — обеспечивает серверный рендеринг, удобную маршрутизацию и отличную интеграцию с React-компонентами.
*   **Язык**: **TypeScript** — для типобезопасности как на фронтенде, так и на бэкенде (в случае Node.js).
*   **Стилизация**: **Tailwind CSS** — для быстрой и гибкой разработки UI.
*   **UI-компоненты**: Библиотека вроде **shadcn/ui** — для создания сложных элементов управления (таймлайн, панель превью, лента фидбека) на основе готовых, доступных компонентов.
*   **Взаимодействие**: **React** + хуки для управления состоянием приложения (например, **Zustand** или **Jotai**), обработки жестов (пин на таймлайне) и отображения виджетов.

### 🛠️ 5. Инфраструктура и CI/CD

*   **Монорепозиторий**: **pnpm workspaces** (для TypeScript/JS частей) — для управления общими пакетами и упрощения разработки.
*   **Контейнеризация**: **Docker** и **Docker Compose** — для воспроизводимого окружения всех сервисов (API, рендереры, базы данных).
*   **CI/CD**: **GitHub Actions** или **GitLab CI**.
*   **Мониторинг**: **Prometheus** + **Grafana** для сбора метрик (время рендеринга, загрузка агентов, ошибки).

### 📝 Резюмирующая таблица

| Слой | Технологии | Обоснование |
| :--- | :--- | :--- |
| **Бэкенд (Ядро)** | Python 3.11+, FastAPI, LangGraph | Лидер в AI, высокая производительность, гибкая оркестрация агентов |
| **Бэкенд (API)** | Hono / Next.js API Routes (TypeScript) | Может использоваться для легковесных API-слоев |
| **Базы Данных** | PostgreSQL + pgvector, Neo4j, Redis | Надежность, векторный поиск, графовые структуры, кэширование |
| **Рендеринг** | Playwright + Headless Chromium, Three.js, FFmpeg | Точность браузерного рендеринга, 3D-возможности, кодирование【9†L16】 |
| **Фронтенд** | Next.js 15, TypeScript, Tailwind CSS | Современный, производительный, с богатой экосистемой |
| **Инфраструктура** | Docker, pnpm, GitHub Actions | Воспроизводимость, масштабируемость, автоматизация |

Предложенный стек — это не догма, а отправная точка, соответствующая ключевым принципам архитектуры: расширяемость через реестры, патчи вместо перегенерации и разделение на смысловой и рендеринговый графы【15†L1-L6】. Он позволяет начать с малого (минутные ролики) и масштабироваться до сложных проектов, не переписывая ядро.
