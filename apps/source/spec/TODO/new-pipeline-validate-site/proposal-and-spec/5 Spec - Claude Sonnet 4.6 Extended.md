Составь чёткую спецификацию, пригодную для разработки.
- Аутентификация. Без неё. На такие страницы не заходим, маркируем их в результате.
- Остальное - наилучшим образом для получения качественного результата.

---

Документ готов. Что вошло в спецификацию и как закрыты все найденные пробелы:

**Критические пробелы — закрыты:**

- `Аутентификация` — явный запрет входа. Страницы с HTTP 401/403 или URL-паттернами /login/auth немедленно маркируются `AUTH_REQUIRED` и пропускаются. В отчёт идёт отдельный раздел «Страницы вне области аудита».
- `HTTP-ошибки` — полная таблица поведения: 404 → HIGH/MEDIUM issue, 5xx → CRITICAL после retry, таймаут → HIGH, цепочка редиректов > 3 → MEDIUM.
- `Confidence-gate в классификации` — при `confidence < 0.75` страница получает `pageType = Unknown`, `riskLevel = HIGH` и немедленно уходит в Human Review.

**Противоречие стадии 8 — исправлено:** явная таблица решений: LOW/MEDIUM + conf ≥ 0.85 → autofix, HIGH (любой conf) → только draft, CRITICAL → только рекомендация.

**Значимые пробелы — закрыты:**

- `Template sampling` — алгоритм через `site-config.templatePatterns` (regex), первый по алфавиту URL как представитель.
- `Embedding model` — зафиксирован `text-embedding-3-small` с порогом similarity 0.92 и confidence-gate 0.5.
- `Site Integrity Score` — явная формула: штрафные очки × уровень, с весами по четырём измерениям (Legal 40%, Content 25%, Language 20%, SEO 15%).
- `SSOT onboarding` — процедура первого запуска с `--extract-config-template`, подтверждение владельцем, Git-фиксация.
- `Нотификация` — webhook при CRITICAL, формат payload, fallback на лог.
- `--force-full` — флаг принудительного полного аудита с описанием сценариев применения.
- `Regression tests` — golden snapshots (50–100 страниц), допустимое отклонение 5% при смене модели.
